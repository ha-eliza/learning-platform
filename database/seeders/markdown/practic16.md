**Цель работы:** Приобретение практических навыков проведения комплексного юзабилити-аудита, тестирования пользовательского интерфейса (UI/UX) веб-ресурса и составления профессиональной технической документации по его улучшению.

---

## 📝 Задание к выполнению
Проведите комплексный юзабилити-аудит и тестирование существующего веб-сайта (на выбор: действующий интернет-магазин, городской портал, образовательная платформа) и сформируйте официальный отчет.
В ходе выполнения работы обязательно реализуйте следующие этапы:

1. **Разработка сценариев (UX-тестирование):**
   * Сформулируйте 3 типовые бизнес-цели для сайта (например: «найти конкретный товар, положить в корзину и оформить заказ без регистрации»).
   * Пошагово пройдите эти сценарии, фиксируя все препятствия (User Pain Points), с которыми сталкивается пользователь.

2. **Эвристический анализ (UI-аудит):**
   * Оцените интерфейс по ключевым критериям: понятность навигации, скорость поиска информации, контрастность текстов, корректность работы форм ввода и адаптивность под мобильные экраны.

3. **Классификация и фиксация дефектов:**
   * Сделайте скриншоты всех найденных ошибок и наглядно разметьте их графическими стрелками/маркерами.
   * Присвойте каждой ошибке статус критичности: *Блокирующая (Critical)*, *Значительная (Major)* или *Минорная/Косметическая (Minor)*.

4. **Оформление итоговой документации:**
   * Составьте отчет в формате таблицы, содержащей столбцы: *ID ошибки*, *Расположение (URL)*, *Описание проблемы со скриншотом*, *Нарушенная эвристика/правило*, *Уровень критичности* и *Рекомендация по исправлению (ТЗ для дизайнера/разработчика)*.

### Вариант 2. Сдача через репозиторий Git
Использование Git — это стандарт современной разработки. Для сдачи работы выполните следующие шаги:

#### Шаг 1. Подготовка локальной папки
Создайте на компьютере отдельную папку для практических работ (например, `web-practics`). Внутри нее создайте папку `task-n`(n - номер задания) и сохраните туда ваше решение.

#### Шаг 2. Инициализация репозитория
Откройте терминал (или Git Bash) в папке проекта и выполните команды:
```bash
# Инициализируем Git в вашей папке
git init

# Добавляем все файлы под контроль версий
git add .

# Делаем первый коммит (фиксацию изменений)
git commit -m "feat: add technical specification for web-site"
```

#### Шаг 3. Создание удаленного репозитория
1. Зайдите на свой аккаунт [GitHub](https://github.com) или [GitLab](https://gitlab.com).
2. Нажмите кнопку **New repository** (Новый репозиторий).
3. Введите имя репозитория (например, `my-web-course`) и выберите тип **Public** (Публичный).
4. Нажмите **Create repository**.

#### Шаг 4. Связывание и отправка кода в облако
Скопируйте ссылку на ваш созданный удаленный репозиторий и вставьте в терминал:
```bash
# Привязываем локальный Git к облаку (замените URL на свой!)
git remote add origin https://github.com

# Переименовываем главную ветку в main
git branch -M main

# Отправляем файлы на сервер
git push -u origin main
```

#### Шаг 5. Отправка ссылки преподавателю
1. Скопируйте итоговую ссылку на ваш публичный репозиторий из адресной строки браузера.
2. В текстовое поле **«Комментарий»** вставьте скопированную ссылку на Git.
3. В нашей системе нажмите кнопку **«Отправить»** под этим заданием.
