## 1. Основные этапы разработки сайта

Процесс разработки веб‑сайта можно разделить на несколько ключевых этапов:

### Этап 1. Планирование и анализ

* определение целей и задач сайта;
* анализ целевой аудитории;
* изучение конкурентов;
* составление семантического ядра (для SEO);
* выбор платформы (CMS, фреймворк или чистая вёрстка);
* определение бюджета и сроков.

### Этап 2. Создание технического задания (ТЗ)

Подробное описание требований к сайту (см. раздел 2).

### Этап 3. Проектирование и дизайн

* создание структуры сайта (sitemap);
* разработка прототипов страниц;
* проектирование UI‑китов и дизайн‑систем;
* создание финальных макетов всех страниц.

### Этап 4. Вёрстка и программирование

* вёрстка макетов (HTML/CSS);
* программирование функционала (JavaScript, PHP и т. д.);
* интеграция с CMS (если используется);
* настройка сервера и базы данных.

### Этап 5. Наполнение контентом

* подготовка и размещение текстов;
* оптимизация и загрузка изображений;
* добавление видео и других медиафайлов.

### Этап 6. Тестирование

* проверка кроссбраузерности;
* тестирование адаптивности;
* отладка JavaScript;
* проверка форм и интерактивных элементов;
* юзабилити‑тестирование;
* SEO‑аудит.

### Этап 7. Запуск и публикация

* перенос на боевой сервер;
* подключение домена;
* настройка SSL‑сертификата;
* финальная проверка работоспособности.

### Этап 8. Поддержка и развитие

* регулярное обновление контента;
* мониторинг работоспособности;
* резервное копирование;
* внедрение нового функционала;
* SEO‑продвижение.

## 2. Техническое задание (ТЗ)

**Техническое задание** — это документ, описывающий требования к разрабатываемому сайту.

### Структура типового ТЗ

1. **Введение**
   * цель создания сайта;
   * целевая аудитория;
   * бизнес‑цели.

2. **Общие требования**
   * платформа разработки;
   * требования к хостингу;
   * поддерживаемые браузеры;
   * адаптивность (мобильные устройства).

3. **Структура сайта**
   * карта сайта (sitemap);
   * иерархия страниц.

4. **Дизайн**
   * цветовая палитра;
   * шрифты;
   * стилистика элементов (кнопки, формы и т. д.).

5. **Функциональные требования**
   * список разделов и их функционал;
   * формы обратной связи;
   * поиск;
   * корзина (для интернет‑магазинов);
   * личный кабинет и т. п.

6. **Требования к контенту**
   * правила написания текстов;
   * требования к изображениям;
   * видео и аудиоматериалы.

7. **SEO‑требования**
   * метатеги;
   * семантическая разметка;
   * ЧПУ (человеко‑понятные URL).

8. **Тестирование**
   * критерии приёмки;
   * чек‑лист тестирования.

9. **Сроки и бюджет**
   * график этапов разработки;
   * стоимость работ.

10. **Приложения**
    * прототипы;
    * примеры дизайна;
    * дополнительные материалы.

## 3. Файловая структура сайта

Пример стандартной структуры для статического сайта:

```
/css/
  style.css
  responsive.css
/js/
  script.js
  plugins.js
/images/
  logo.png
  slider/
    slide1.jpg
    slide2.jpg
/fonts/
  custom-font.woff
index.html
about.html
contacts.html
```

### Рекомендации по организации файловой структуры

* создавайте отдельные папки для разных типов файлов;
* используйте понятные названия папок на английском языке;
* группируйте изображения по категориям;
* разделяйте CSS и JS на несколько файлов (основной + дополнительные);
* избегайте вложенности более 3–4 уровней;
* сохраняйте исходники в отдельной папке (например, `/src/`).

## 4. Два типа графики на web‑сайтах

### Растровая графика

**Характеристики:**
* состоит из пикселей;
* при увеличении теряет качество;
* подходит для фотографий и сложных изображений.

**Форматы:**
* **JPEG** — для фотографий (сжатие с потерями);
* **PNG** — для изображений с прозрачностью (сжатие без потерь);
* **GIF** — для простой анимации;
* **WebP** — современный формат с лучшим сжатием.

### Векторная графика

**Характеристики:**
* описывается математическими формулами;
* масштабируется без потери качества;
* малый размер файла для простых изображений;
* идеально подходит для иконок, логотипов, схем.

**Форматы:**
* **SVG** — основной формат для веба;
* **AI** — родной формат Adobe Illustrator (для исходников);
* **EPS** — устаревший формат, редко используется в вебе.

**Рекомендации:**
* используйте SVG для иконок и логотипов;
* применяйте WebP или оптимизированный JPEG для фотографий;
* PNG — для изображений с прозрачностью;
* оптимизируйте все изображения перед загрузкой (сжимайте без потери качества).

## 5. Имена файлов

Правильные имена файлов важны для:
* удобства работы разработчиков;
* SEO (поисковая оптимизация);
* корректной работы скриптов и стилей;
* совместимости с разными системами.

### Правила именования файлов

1. Используйте только латинские буквы, цифры и символы `-` или `_`.
2. Избегайте пробелов (используйте `-` или `_` вместо них).
3. Пишите строчными буквами (из‑за чувствительности к регистру на некоторых серверах).
4. Делайте имена осмысленными и короткими.
5. Используйте ключевые слова для SEO (например, `product-slider.jpg` вместо `img123.jpg`).
6. Для многоязычных сайтов используйте транслитерацию.
7. Добавляйте версию или дату при необходимости (например, `style-v2.css`).

### Примеры правильных и неправильных имён

| Правильно | Неправильно | Причина |
|--------|-----------|-------|
| `main-style.css` | `Main Style.css` | Пробел и заглавная буква |
| `header-logo.svg` | `logo для шапки.png` | Кириллица и пробел |
| `slider-image-1.jpg` | `IMG_001.JPG` | Неинформативно, заглавные буквы |
| `user-profile.js` | `script.js` | Слишком общее имя |
| `about-us-page.html` | `about us.html` | Пробел |

### Дополнительные рекомендации

* для изображений товаров используйте схему: `category-product-feature.jpg` (например, `shoes-sneakers-blue.jpg`);
* для CSS и JS файлов указывайте назначение: `main-styles.css`, `slider-script.js`;
* для резервных копий добавляйте дату: `backup-2023-10-01.zip`;
* соблюдайте единообразие в именовании по всему проекту.

## Заключение

Соблюдение этих принципов на всех этапах разработки — от составления ТЗ до организации файловой структуры — позволит создать качественный, удобный и оптимизированный веб‑сайт. Правильная организация работы сэкономит время на разработку и упростит дальнейшую поддержку проекта.

> **Совет:** создайте шаблон структуры проекта и стандарт именования файлов, который будет использоваться во всех ваших работах. Это повысит эффективность команды и обеспечит единообразие проектов.
